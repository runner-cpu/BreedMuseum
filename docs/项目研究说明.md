## 0. 一页速览（PPT 封面/摘要可直接用）

**一句话定位**

> 把 46 页官方名录 PDF，变成一张公众愿意先看见、再去查证的地方畜禽品种数据地图。

**四个核心数字**

| 数字 | 含义 |
| --- | --- |
| **1186** | 站内馆藏记录（覆盖 31 个省级行政区、15 个类别） |
| **667** | 带可用图片、面向访客浏览的展品集合 |
| **202** | 667 条记录按真实坐标聚合出的产区点位（覆盖 30 个省级行政区） |
| **271 / 271** | 农业农村部第 940 号公告畜禽名称的匹配率 |

**三个关键词**

`证据边界` · `空间叙事` · `可复现的视觉结论`

**作品形态**

纯静态 Web 应用（React 18 + TypeScript + Vite + SVG），GitHub Pages 托管，无后端、无账号、无第三方在线 AI 调用。

## 1. 立题依据

### 1.1 一句话结论

> 地方畜禽遗传资源的数据并不稀缺，稀缺的是**让公众愿意进入、并且能够判断可信度的入口**。

### 1.2 背景：一份"查得到、却看不进去"的国家家底

我国是世界畜禽遗传资源大国。农业农村部公告第 940 号《国家级畜禽遗传资源保护名录》收录 298 个品种（畜禽 271、蜂 12、蚕 15）；国家畜禽遗传资源委员会《国家畜禽遗传资源品种名录（2024 年版）》（畜资委办〔2025〕18 号）进一步收录 1129 条资源（畜禽 1090、蜂 39）。

但这些数字对公众几乎是"隐形"的：

- 载体是 **46 页 PDF**、普查公告与各县地方志，阅读门槛高、检索能力弱；
- 同一品种在不同资料中名称不一（规范名、别名、俗名、同音误写），普通用户难以对齐；
- 保护身份、濒危等级、生产性能混在不同表格里，**没有任何一处告诉读者"这条信息可信到什么程度"**；
- 现有科普内容多以图文列表呈现，缺少"空间—类别—保护身份"三者同屏的入口。

### 1.3 政策与社会依据

| 层面 | 依据 | 对本项目的意义 |
| --- | --- | --- |
| 国家战略 | 种业振兴行动、生物多样性保护 | 地方品种是种业自主的基因基础，公众认知是保护的前提 |
| 文化传承 | 农耕文明保护、乡村文化振兴 | 地方品种承载地域生态与育种经验，是"活着的农业遗产" |
| 科学普及 | 全民科学素质行动 | 需要把专业名录转译为公众可读、可玩、可核对的科普产品 |
| 数字文化 | 国家文化数字化战略 | 鼓励以可视化、交互化方式盘活公共数据资源 |

### 1.4 现有产品的四个缺口

1. **入口缺口**：官方资料以 PDF/表格为主，缺少"先看见"的视觉钩子；
2. **口径缺口**：站内馆藏数、国家级保护品种数、濒危等级常被混为一谈，公众容易误读；
3. **证据缺口**：权威数据、编辑推断、待核验信息混排，读者无法判断某条结论的证据级别；
4. **设备缺口**：不少数据可视化作品依赖 WebGL/3D，在手机、低端笔记本、教室投影上降级严重。

### 1.5 研究问题

本项目要回答三个问题：

- **Q1 转译**：如何把名录型公共数据转成公众愿意停留的视觉叙事，而不牺牲信息密度？
- **Q2 可信**：如何让"证据边界"成为界面的一部分，而不是藏在脚注里？
- **Q3 复用**：如何让视觉结论可被测试与复现，避免"图好看但口径漂移"？

### 1.6 选题价值

- **社会价值**：为地方品种保护提供公众入口，把"你家的省份亮了几个"变成地域认同的抓手；
- **教育价值**：可用于中小学科普、农业院校教学、研学课程；
- **方法价值**：为名录类公共数据（非遗、地理标志、农作物品种等）提供可复用的"可视化 + 证据治理"范式。

## 2. 研究内容与方法

### 2.1 总体框架

```
┌─────────────────────────────────────────────────────────┐
│  数据层：官方台账 → 运行时馆藏 → 三级核验元数据          │
├─────────────────────────────────────────────────────────┤
│  可视化层：省块色阶 → 产区聚类 → 类别切片 → 镜头筛选     │
├─────────────────────────────────────────────────────────┤
│  交互层：地图探索 / 品种百科 / 数据看板 / 对比 / 互动厅  │
├─────────────────────────────────────────────────────────┤
│  验证层：纯函数单测 → 数据审计 → E2E → 包体预算 → CI     │
└─────────────────────────────────────────────────────────┘
```

### 2.2 研究内容（五项）

#### 内容一：名录型数据的结构化与治理

- 以农业农村部第 940 号公告、2024 年版名录官方 PDF 为基线，逐页核对建立机器可读台账；
- 统一规范名、别名、英文名、省份、类别、坐标、保护身份、濒危标注等字段；
- 建立 **三级核验状态**：
  - `official`：官方名录或 940 号公告可追溯；
  - `editorial`：项目整理资料（如编辑口径濒危标签）；
  - `pending`：仍待专项核验（如历史外链图片授权、部分产区坐标）。
- 运行时收敛为 1186 条唯一记录（唯一 ID / 唯一规范名），数据审计问题为 0。

#### 内容二：产区空间聚合与地图可视化

- 把 1062 条可落点记录（509 个不同坐标）聚合为 **217 个全量产区簇**；地图实际绘制带图记录 667 条 → **202 个点位**；
- 聚合规则：**同省 + 平面距离 ≤ 0.14（约 150 km）**，簇中心为记录数加权重心；
- 采用"双向约束贪心合并"：新成员到新中心要够近，且中心移动后原成员仍须在半径内——保证结果与遍历顺序无关、簇内最大偏移不超过半径；
- 省块采用五档鼠尾草—森林绿色阶，映射该省已核验记录量；点位按记录数分级半径，≥5 条标注数量。

#### 内容三：多轴筛选与"镜头"叙事

- 两条可叠加的筛选轴：
  - **类别轴**：15 类畜种（可浏览 14 类）；
  - **镜头轴**：全部落点 / 国家级保护（252 条可浏览记录）/ 濒危之窗（82 条编辑口径）。
- 镜头只改变"哪条记录算数"，**不移动簇的位置**，避免同一产区在切换时"跳动"；
- 每个镜头自带计数，点击前即可知道该组合是否为空。

#### 内容四：从"看"到"玩"的互动装置

三台装置，题目全部由已核验字段生成，随机数由显式种子驱动、可复现：

| 装置 | 题量 | 交互 | 设计红线 |
| --- | --- | --- | --- |
| 找家挑战 | 3 题 | 在真实中国地图上点产区，答错给出与真实产区的公里差 | 只用有已核验坐标的记录 |
| 识图挑战 | 6 题 | 看馆藏真实照片选类别 | 只问类别、不问品种名（照片品种归属待核验） |
| 知识问答 | 5 题 | 类别 / 产区 / 保护身份 / 濒危口径四类题 | 待核验记录不作题干与干扰项 |

答题界面按主流 quiz 范式重构：进度条 + 题号 + 得分 chip；A/B/C/D 字母选项卡；即时 ✓/✗ 反馈 + 解析 + 下一题；结算页含正确率与逐题回顾。

#### 内容五：视觉系统与无障碍

- 设计令牌：宣纸底 + 墨绿主色 + 朱砂信号色，浅/深两套由同一份 `stagePalette.ts` 驱动 CSS 与 SVG；
- 深色模式下所有类别色自动提亮至与省块、面板对比度 ≥ 3.2:1；
- 键盘可操作省份、点位、镜头与答题选项；`prefers-reduced-motion` 下直接呈现静态帧；
- 移动端 390px 完整适配，触控目标 ≥ 44px。

## 3. 创新点与可行性

### 3.1 创新点

#### 创新一：把"证据边界"做成可视化通道，而不是脚注

- **是什么**：省块色阶只映射已核验记录量；124 条待核验产区记录保留在百科但从不落点；濒危镜头明确标注"编辑口径、非权威结论"；识图挑战只问类别、不问品种名。
- **为什么新**：同类作品通常把权威数据、编辑推断与待核验项混排，读者无法判断证据级别；本项目把三级核验状态直接编码进界面与文案。
- **证据**：`/dashboard` 的覆盖度说明、`/audit/` 公开审计页、`breedMetadata` 元数据层、数据审计 0 问题。

#### 创新二：语义明确的产区聚合，而不是"把点铺开"

- **是什么**：同省 + ≤0.14 的双向约束贪心合并，簇中心为加权重心，簇内记录数即"同产区品种数"。
- **为什么新**：常见做法是把同坐标记录按固定角度铺在圆环上，点的数量、角度都不对应任何字段；本项目让每个簇的大小、数字、分段颜色都有明确含义。
- **证据**：`clusterSites.ts` 纯函数 + 单测断言"每条记录恰好属于一个簇""成员到中心距离 ≤ 半径""输入顺序无关"。

#### 创新三：视觉结论可被测试与复现

- **是什么**：聚合、筛选、出题范围全部实现为纯函数；同一随机种子可复现同一局题目；包体预算、文档同步、数据审计全部进 CI。
- **为什么新**：可视化项目常见"图好看但口径漂移"，本项目把口径写进测试与发布门禁。
- **证据**：37 个测试文件 / 162 项 Vitest；35 个 Playwright 用例 × 双视口 = 70 项运行；`pnpm check` 一条命令串起 8 道门禁。

#### 创新四：2D SVG 的"设备平权"

- **是什么**：放弃 3D/WebGL，用 SVG + CSS 完成省块、点位、镜头与详情面板。
- **为什么新**：在手机、低端笔记本、教室投影上给出与桌面一致的信息密度；键盘操作与"减少动态效果"真正可用。
- **证据**：390px 移动端 E2E、`prefers-reduced-motion` 静态帧、无 WebGL 依赖。

## 5. PPT 分页脚本（18 页，建议 8 分钟）

> 每页给出：标题 / 画面 / 要点 / 讲稿（约 20–35 秒）/ 建议时长

### P1 封面（15 秒）

- **标题**：中国地方畜禽品种数字博物馆
- **副标题**：一张可查证的地方品种数据地图
- **画面**：深色地图底图 + 202 个点位微光
- **讲稿**：各位评委好，我们的作品是中国地方畜禽品种数字博物馆。我们想解决的，是一份 46 页的官方名录，公众为什么看不进去。

### P2 一句话与四个数字（20 秒）

- **画面**：1186 / 667 / 202 / 271 四个大数字
- **讲稿**：1186 条馆藏，667 条带图可浏览，聚成 202 个产区点位，第 940 号公告 271 个畜禽名称全部匹配。这是我们的数据底座。

### P3 立题依据：三个断层（30 秒）

- **画面**：左侧 PDF 截图，右侧"查得到 / 看不进 / 信不过"三个词
- **讲稿**：数据并不稀缺，稀缺的是入口。官方资料是 46 页 PDF，名称不统一，保护身份和濒危标签混在一起，公众既看不进去，也无法判断可信度。

### P4 研究问题（20 秒）

- **画面**：Q1 转译 / Q2 可信 / Q3 复用
- **讲稿**：所以我们给自己提了三个问题：怎么转译、怎么让人信、怎么让结论可复现。

### P5 总体框架（25 秒）

- **画面**：数据层—可视化层—交互层—验证层四层图
- **讲稿**：整个系统分四层：数据治理、可视化编码、交互叙事、工程验证。每一层都有对应的产出和门禁。

### P6 研究内容一：数据治理（30 秒）

- **画面**：1129 条台账 → 1186 条运行时 → 三级核验徽章
- **讲稿**：我们逐页核对官方 PDF，建立 1129 条机器可读台账，运行时收敛为 1186 条唯一记录，并给每条记录标注 official / editorial / pending 三级核验状态。

### P7 研究内容二：空间聚合（35 秒）

- **画面**：左"同坐标铺圆环"错误示意，右"202 个产区簇"正确示意
- **讲稿**：1062 条可落点记录只落在 509 个坐标上，最大的一个坐标挤了 45 条。我们不做人工铺点，而是同省、150 公里内做双向约束合并，簇中心是加权重心。于是每个点的大小和数字都有含义：这个产区有多少个品种。

### P8 研究内容三：多轴镜头（30 秒）

- **画面**：全部落点 667 → 国家级保护 252 → 濒危之窗 82 三段切换
- **讲稿**：类别和镜头是两条可叠加的轴。镜头只改变哪条记录算数，不移动点位，所以切换时地图不会跳。每个镜头自带计数，点之前就知道有没有内容。

### P9 研究内容四：互动厅（30 秒）

- **画面**：三台装置截图 + 答错的距离反馈
- **讲稿**：三台装置全部从已核验字段出题。找家挑战答错会告诉你差了多少公里；识图挑战只问类别，因为照片能证明它是一头猪，还不能证明它是哪一头。

### P10 研究内容五：视觉与无障碍（25 秒）

- **画面**：浅色 / 深色双主题对照 + 390px 移动端
- **讲稿**：浅色是宣纸与墨绿，深色是石墨绿与苔绿；所有类别色在深色下自动提亮到可读对比度。地图、答题、筛选全部键盘可操作，减动效时直接给静态帧。

### P11 创新点一：证据边界可视化（30 秒）

- **画面**：124 条待核验 / 82 条编辑口径 / 识图只问类别
- **讲稿**：我们的第一个创新，是把证据边界做成界面的一部分。124 条待核验产区保留在百科但从不落点；濒危标签写明是编辑口径；识图挑战宁可降一级，也不拿待核验身份当答案。

### P12 创新点二：语义明确的聚合（25 秒）

- **画面**：簇内类别分段 + 记录数标签
- **讲稿**：第二个创新是聚合本身有语义。簇的大小、数字、分段颜色都对应真实字段，而不是为了好看把点铺开。

### P13 创新点三：可复现（25 秒）

- **画面**：`pnpm check` 输出 + 162 项测试
- **讲稿**：第三个创新是视觉结论可被测试。聚合、筛选、出题都是纯函数；一条命令跑完类型、lint、162 项单测、数据审计、文档同步、构建、包体预算和双视口 E2E。

### P14 创新点四：设备平权（20 秒）

- **画面**：手机 / 平板 / 投影同屏
- **讲稿**：我们放弃 3D，用 SVG，让手机、低端笔记本和教室投影拿到同一份信息密度。

### P15 可行性（25 秒）

- **画面**：六维可行性表 + 线上二维码
- **讲稿**：技术、数据、工程、时间、成本都可控。作品已经上线，CI 全绿，纯静态托管零成本。主要风险是图片授权，我们用原创占位和逐条公开状态来控制。

### P16 研究安排（25 秒）

- **画面**：三阶段已完成 + 四阶段计划时间轴
- **讲稿**：9 月底完成数据底座，10 月中完成信息架构，10 月下旬完成视觉与互动重构并上线。接下来三周是材料、视频和答辩准备。

### P17 预期成果（20 秒）

- **画面**：作品 / 数据 / 方法 / 材料四象限
- **讲稿**：成果分四类：一个线上作品、一套结构化数据、一套可复用方法、一整套参赛材料。

### P18 收尾（15 秒）

- **画面**：全图拉远 + 一句话
- **讲稿**：我们做的不是一份更好看的表格，是一张让人愿意先看见、再去查证的地图。谢谢各位评委。

## 6. 答辩 Q&A 预案

**Q1：为什么不用 3D / WebGL？**
A：本项目只需要让"位置"和"证据边界"被所有设备看见。2D 在手机、低端笔记本、教室投影上给出同一份信息密度，也让键盘操作与减动效真正可用。3D 会抬高设备门槛，却不增加信息。

**Q2：202 个点和 1062 条是什么关系？**
A：1062 是全量可落点口径，聚合为 217 簇，只在文档和覆盖度图表引用；地图实际绘制的是 667 条带图记录，聚合为 202 个点位。两个口径不能混用。

**Q3：为什么有 124 条不显示在地图上？**
A：这 124 条省份待核验。我们不用 `(0,0)` 伪造落点，也不猜坐标；它们保留在百科中可检索，并标注待核验，但不进地图与省份统计。

**Q4：濒危标签权威吗？**
A：不权威，是我们主动标注为"编辑口径"的 82 条，页面写明"非权威结论"。首页钩子句用 1186 而不是濒危数字，就是为了不误导。

**Q5：图片版权怎么处理？**
A：三类来源分级标注：已核验授权本地镜像（目前 0 张）、项目原创 SVG（519 张）、历史 CDN 外链待核验（667 张）。`/audit/breed-images.csv` 逐条公开状态，并开放勘误渠道。

**Q6：数据会不会过时？**
A：数据版本 2026-09-27，文档与页面由同一生成器同步；新增记录必须通过唯一性、枚举、坐标、来源、名录匹配五类审计才能进入构建。

**Q7：和同类地图可视化比，差异在哪？**
A：同类作品通常按省上色或用飞线；我们把每条可落点记录聚合到真实产区坐标，点位可直接打开百科详情，且镜头、筛选和显示边界都写成可测试的数据函数。

**Q8：手机能用吗？**
A：全部页面适配 390px，E2E 含移动端场景；地图按需渲染点位，减动效时走静态帧，互动厅与百科详情共用同一套轻量交互。

## 8. 可直接引用的三句话

1. **定位句**：我们做的不是一份更好看的表格，是一张让人愿意先看见、再去查证的地图。
