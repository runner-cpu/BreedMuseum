# 部署与维护指南

更新日期：2026-10-07

## 1. 公开入口

- 公开网站：https://runner-cpu.github.io/BreedMuseum/
- 全面审计与改进报告：https://runner-cpu.github.io/BreedMuseum/audit/
- 隐私与 AI 使用说明：https://runner-cpu.github.io/BreedMuseum/privacy.html
- GitHub 仓库：https://github.com/runner-cpu/BreedMuseum

源码以 main 分支为准，公开站点由 GitHub Actions（deploy-pages.yml）在质量门禁通过后从 main 的构建产物自动发布；项目使用 HashRouter，公开路由不依赖服务器回退规则。gh-pages 分支是历史遗留的静态快照镜像，仅按交付要求手动同步，不作为常规发布渠道，也不要把仓库 Pages Source 改回分支模式。

## 2. 环境要求

- Node.js 20 或更高版本。
- pnpm，安装依赖时优先使用 pnpm install --frozen-lockfile。
- Chromium，仅在运行 Playwright E2E 时需要。
- Python 3，仅在重新生成 PDF 手册时需要，并先安装 requirements-docs.txt。

Supabase、Sentry 和 AI 相关变量均为可选。公共科普站在没有这些变量时仍应完整可用。任何真实密钥都不得写入仓库、构建日志或分支历史。

## 3. 发布前检查

在源码分支执行：

~~~powershell
pnpm install --frozen-lockfile
pnpm check:all
pnpm build:pages
~~~

pnpm check:all 会依次执行 TypeScript、Biome、Vitest、Pages 打包测试、数据与文档一致性、生产构建、包体预算以及桌面/移动端 E2E。若本机已有预览服务占用 `127.0.0.1:46217`，请设置其他 `E2E_PORT` 后再运行 Playwright，并在发布记录中写明实际结果。

pnpm build:pages 会生成 dist，并额外准备：

- dist/audit/index.html：公开 HTML 审计报告。
- dist/audit/项目全面审计与改进报告.md：报告原始 Markdown。
- dist/audit/breed-images.csv：品种图片索引（含来源状态、作者与授权列）。
- dist/public/brand：审计报告引用的 SVG 品牌资产。
- dist/privacy.html、dist/robots.txt、dist/sitemap.xml、dist/site.webmanifest：公开静态说明与搜索引擎元数据。
- dist/.nojekyll：防止 GitHub Pages 使用 Jekyll 改写静态目录。

## 4. 发布流程（GitHub Actions）

推送 main 后，deploy-pages.yml 自动执行：

1. **quality**：复用 quality.yml 完整门禁（依赖审计、类型、lint、Vitest、文档一致性、生产构建、包体预算、Pages 打包、桌面/390px E2E）。
2. **build**：门禁通过后执行 `pnpm build:pages` 并上传 dist 产物。
3. **deploy**：`actions/deploy-pages` 发布到 github-pages 环境。

任何一步失败都会阻断发布；不存在“质量失败但 Pages 成功”的路径。部署历史可在仓库 Actions 页面按 commit SHA 核对。

## 4b. gh-pages 遗留镜像（仅按交付要求）

如需维护 legacy gh-pages 快照，使用独立 worktree，避免把构建产物混入源码分支：

~~~powershell
git worktree add ..\BreedMuseum-pages gh-pages
~~~

确认 Actions 部署成功且本地 dist 为同一 commit 的验证产物后，在 gh-pages worktree 中删除旧的已跟踪构建文件，再复制 dist 的完整内容：

~~~powershell
git -C ..\BreedMuseum-pages rm -r -- .
Get-ChildItem -Force .\dist | Copy-Item -Destination ..\BreedMuseum-pages -Recurse -Force
git -C ..\BreedMuseum-pages add --all
git -C ..\BreedMuseum-pages commit -m "deploy: sync legacy mirror from main <sha>"
git -C ..\BreedMuseum-pages push origin gh-pages
~~~

不要使用强制推送覆盖 gh-pages。若远端包含其他人的新提交，应先 fetch 并检查差异。

## 5. 发布后验证

GitHub Pages 通常需要几十秒完成部署。至少检查：

1. 网站首页返回 HTTP 200，favicon 和 CSS/JS 正常加载。
2. 百科、地图、数据看板、对比、AI 和未知路径页面可打开。
3. https://runner-cpu.github.io/BreedMuseum/audit/ 返回 HTTP 200。
4. https://runner-cpu.github.io/BreedMuseum/privacy.html 返回 HTTP 200，robots.txt 的 sitemap 地址可访问。
5. 审计报告中的四个 SVG 图标全部加载，桌面端和 390px 手机端无横向溢出。
6. GitHub Actions 的 Pages 部署指向本次发布提交；gh-pages 镜像（如已同步）同样指向该提交。

## 6. 数据与文档维护

新增或修改品种记录时：

1. 先补充来源、规范名称、别名、核验日期与图片权利信息。
2. 为预期行为补充失败测试，再修改运行时数据。
3. 执行 pnpm data:audit 和 pnpm docs:sync。
4. 如 Markdown 手册发生变化，重新生成相应 PDF。
5. 执行 pnpm check:all，确认文档统计、测试和 E2E 全部通过；若 E2E 失败，不得将发布标记为全链路通过，应记录失败用例和原因后再修复复跑。

无法证明图片可复用时，应继续使用 public/brand/breed-placeholder.svg，不得编造作者或授权状态。

数据版本（当前为 2026-09-27）表示运行时馆藏快照与来源核对版本；文档审计日期表示本次代码、构建、文档和发布流程复核日期，两者不要混写。

## 7. 回滚

源码变更优先使用 git revert 生成可审计的反向提交。Pages 发布异常时 revert main 上的相关提交并推送，让 Actions 重新走完整门禁后自动回滚公开站点；不要绕过门禁手动发布。

修改前备份保存在 BreedMuseum-backups 目录，包括源码 ZIP、完整 Git bundle 与 SHA-256 清单，可用于恢复未提交文件或完整分支历史。

## 8. 已知限制

- breeds 懒加载数据块仍超过 Vite 默认 500 KB 提示阈值（当前约 750 KiB 级，gzip 约 175 KiB），已纳入 bundle:check 的懒加载预算门禁；后续可按分类或搜索时机进一步拆分。
- 历史图片来源和授权尚未逐条完成复核；已核验授权的本地镜像图片会登记在 src/data/breedImageOverrides.ts 并在图片索引 CSV 中单列。
- AI 服务上线前仍需补齐供应商、用途、保留期与删除方式等正式隐私说明。
- 蜂和蚕暂未纳入常规馆藏指标（名录蜂资源以条目式收录，蚕未收录），因为当前五维畜禽指标模型不适用。
- Playwright 双视口门禁已通过：24 个用例中 23 项通过、1 项按桌面条件跳过、0 项失败；后续仍需加入无障碍自动扫描和覆盖率趋势。
