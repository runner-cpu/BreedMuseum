# 部署与维护指南

更新日期：2026-09-28

## 1. 公开入口

- 公开网站：https://runner-cpu.github.io/BreedMuseum/
- 全面审计与改进报告：https://runner-cpu.github.io/BreedMuseum/audit/
- GitHub 仓库：https://github.com/runner-cpu/BreedMuseum

源码以 main 分支为准，GitHub Pages 的静态构建产物保存在 gh-pages 分支。项目使用 HashRouter，公开路由不依赖服务器回退规则。

## 2. 环境要求

- Node.js 20 或更高版本。
- pnpm，安装依赖时优先使用 pnpm install --frozen-lockfile。
- Chromium，仅在运行 Playwright E2E 时需要。
- Python 3，仅在重新生成 PDF 手册时需要，并先安装 requirements-docs.txt。

Supabase、Sentry 和 AI 相关变量均为可选。公共科普站在没有这些变量时仍应完整可用。任何真实密钥都不得写入仓库、构建日志或 gh-pages 分支。

## 3. 发布前检查

在源码分支执行：

~~~powershell
pnpm install --frozen-lockfile
pnpm check:all
pnpm build:pages
~~~

pnpm check:all 会依次执行 TypeScript、Biome、Vitest、Pages 打包测试、数据与文档一致性、生产构建、包体预算以及桌面/移动端 E2E。

pnpm build:pages 会生成 dist，并额外准备：

- dist/audit/index.html：公开 HTML 审计报告。
- dist/audit/项目全面审计与改进报告.md：报告原始 Markdown。
- dist/public/brand：审计报告引用的 SVG 品牌资产。
- dist/.nojekyll：防止 GitHub Pages 使用 Jekyll 改写静态目录。

## 4. 发布到 gh-pages

推荐使用独立 worktree，避免把构建产物混入源码分支：

~~~powershell
git worktree add ..\BreedMuseum-pages gh-pages
~~~

确认 pnpm build:pages 已通过后，在 gh-pages worktree 中删除旧的已跟踪构建文件，再复制 dist 的完整内容：

~~~powershell
git -C ..\BreedMuseum-pages rm -r -- .
Get-ChildItem -Force .\dist | Copy-Item -Destination ..\BreedMuseum-pages -Recurse -Force
git -C ..\BreedMuseum-pages add --all
git -C ..\BreedMuseum-pages commit -m "deploy: publish verified site"
git -C ..\BreedMuseum-pages push origin gh-pages
~~~

不要使用强制推送覆盖 gh-pages。若远端包含其他人的新提交，应先 fetch 并检查差异。

## 5. 发布后验证

GitHub Pages 通常需要几十秒完成部署。至少检查：

1. 网站首页返回 HTTP 200，favicon 和 CSS/JS 正常加载。
2. 百科、地图、数据看板、对比、AI 和未知路径页面可打开。
3. https://runner-cpu.github.io/BreedMuseum/audit/ 返回 HTTP 200。
4. 审计报告中的四个 SVG 图标全部加载，桌面端和 390px 手机端无横向溢出。
5. GitHub 仓库 main 与 gh-pages 分支均指向本次发布提交。

## 6. 数据与文档维护

新增或修改品种记录时：

1. 先补充来源、规范名称、别名、核验日期与图片权利信息。
2. 为预期行为补充失败测试，再修改运行时数据。
3. 执行 pnpm data:audit 和 pnpm docs:sync。
4. 如 Markdown 手册发生变化，重新生成相应 PDF。
5. 执行 pnpm check:all，确认文档统计、测试和 E2E 全部通过。

无法证明图片可复用时，应继续使用 public/brand/breed-placeholder.svg，不得编造作者或授权状态。

## 7. 回滚

源码变更优先使用 git revert 生成可审计的反向提交。Pages 发布异常时，在 gh-pages 分支 revert 最近一次部署提交并正常 push，避免使用 force push 改写公开历史。

修改前备份保存在 BreedMuseum-backups 目录，包括源码 ZIP、完整 Git bundle 与 SHA-256 清单，可用于恢复未提交文件或完整分支历史。

## 8. 已知限制

- breeds 静态数据块约 696 KB，仍超过 Vite 默认 500 KB 提示阈值，已列入后续拆分计划。
- 历史图片来源和授权尚未逐条完成复核。
- AI 服务上线前仍需补齐供应商、用途、保留期与删除方式等正式隐私说明。
- 蜂和蚕暂未纳入馆藏，因为当前五维畜禽指标模型不适用。
