# 中国畜禽遗传资源数字博物馆综合质量升级设计

日期：2026-09-27  
状态：已批准（2026-09-27，交互、数据口径和改造范围已确认）

## 1. 背景与目标

改造前项目已经具备首页、品种地图、数据看板、品种百科、品种对比和 AI 助手等完整展示链路，运行时共加载 687 条品种数据，主视觉也已形成“墨绿、宣纸、金色”的国风方向。但审查发现，数据唯一性和可追溯性、无后端配置时的可用性、移动端信息架构、页面元信息、资源体积、图片容错、测试与文档等方面仍存在明显短板。

本轮升级的目标是：

1. 以权威名录为基准补齐可信的畜禽品种，不以凑数量为目标。
2. 修复会直接影响展示正确性的重复 ID、错误匹配和配置依赖问题。
3. 建立可持续的数据来源、校验和统计机制，避免文档与页面数字继续漂移。
4. 以全套原创 SVG 品牌资产替换临时文字圆标和遗留模板图标。
5. 在保留现有国风气质的前提下，系统改善视觉、移动端、无障碍、性能、SEO、可靠性和文档。
6. 用自动化测试锁住关键行为，为后续数据扩充和功能迭代提供安全网。

## 2. 已确认的范围边界

### 2.1 本轮包含

- 畜禽品种数据补缺、别名归一、重复 ID 修复和来源标注。
- 页头徽标、横版字标、favicon、图片缺失占位符四类 SVG 品牌资产。
- 首页、地图、看板、百科、对比、AI、404 及全局布局的均衡深度整治。
- 静态科普功能与 Supabase 解耦。
- 路由拆包、图片容错、SEO、键盘操作、减少动画偏好和移动端适配。
- Vitest 单元/组件测试与 Playwright 桌面、390px 移动端烟雾测试。
- README、网站说明书、数据手册、图片索引及综合审计报告同步更新。

### 2.2 本轮不包含

- 蜂和蚕品种。农业农村部 2025 年第 940 号公告另列 12 个蜂品种和 15 个蚕品种；现有“肉、奶、繁殖、役用、适应性”五维性能模型不适合直接套用。本轮在审计报告中记录该模型债务，后续先扩展指标模型再纳入。
- 登录、收藏等已移除功能的恢复。相关陈旧说明会从文档中删除。
- 批量生成品种写实图片。现有外链图片先通过可靠占位和来源说明降级；图片版权与替换优先级进入审计报告。
- 重写 Git 历史以清除既有环境文件。当前提交只停止继续跟踪真实部署配置并提供示例；如需清理历史，应在独立维护窗口执行并轮换相关凭据。

## 4. 现状审计摘要

### 4.1 数据与内容

- 改造前运行时共有 687 条记录，分类统计与当时文档一致，但数字被散落硬编码为 568、592、628、687 等多个历史版本。
- 存在 11 组重复 ID：`bamei-pig`、`xining-horse`、`huai-pig`、`fuzhou-cattle`、`pingwu-cattle`、`xuwen-cattle`、`leizhou-cattle`、`fuan-cattle`、`ganxi-cattle`、`jinjiang-cattle`、`guangfeng-cattle`。这会产生 React key 警告，并可能打开错误品种详情。
- 数据分散在主文件和 14 个增量文件中，没有自动检查唯一性、坐标、枚举、雷达范围、图片字段或来源。
- 大量叙述和外链图片缺少逐条来源、核对日期与版权状态，可信度难以判断。
- 中文品种名与官方名录之间存在缺项、简称和别名混用。

### 4.2 功能与可靠性

- Supabase 客户端在模块加载时强制初始化；本地没有环境变量时，原本可以纯静态运行的科普页面也会白屏。
- 未知路由直接回到首页，不是真正的 404，用户无法区分地址错误和首页跳转。
- 外链图片加载失败时仅隐藏图片，卡片和详情会留下大块空白。
- 项目没有测试文件，回归主要依赖人工浏览。

### 4.3 体验、视觉与移动端

- 页头使用单字圆形临时标，公开目录仍保留 TailAdmin 风格的旧 logo，品牌表达不统一。
- 移动端顶部导航横向截断，搜索、主题、语言和菜单争抢有限宽度；筛选与地图详情阅读拥挤。
- 多处按钮和图标触控目标小于 44×44px，焦点态、跳转主内容和减少动画偏好不完整。
- 页面缺少稳定、层级清晰的 H1；视觉层次、留白和信息密度仍有精修空间。

### 4.4 性能、SEO 与工程

- 当前生产主 JavaScript 包约 2.63 MB，gzip 约 754 KB；AI、PDF 和图表等重依赖随首屏一起进入。
- `vite.config.ts` 在 ESM 配置中使用 `__dirname`，Vite 给出兼容性警告。
- 实际页面没有有效使用 title 和 meta description；现有 `PageMeta` 只出现在未接入的 NotFound 页面。
- `.env.production` 被 Git 跟踪。即使 Supabase anon key 面向浏览器公开，真实部署配置也不应作为项目默认配置长期留在版本库。
- README 和说明书仍描述已移除的登录、收藏功能，部署、数据和功能现状不一致。

## 5. 数据升级设计

### 5.1 权威基线与表达边界

本轮以农业农村部 2025 年第 940 号公告《国家级畜禽遗传资源保护名录》为国家级保护名录基线：

- 官方页面：<https://www.moa.gov.cn/govpublic/nybzzj1/202510/t20251029_6478525.htm>
- 公告口径：271 个畜禽品种、12 个蜂品种、15 个蚕品种。
- 本轮核对日期：2026-09-27。

改造前站内 687 条记录并不等于“687 个国家级保护品种”；改造后最终总数为 701。页面必须区分“站内收录”“国家级保护名录收录”“名称待进一步核验”，不能把全部站内记录暗示为公告名录成员。

### 5.2 补缺与别名策略

初步精确名称比对得到以下候选，实施时须再次按公告正文和可靠资料逐项复核后落库：

- 牛、驴：独龙牛、青海毛驴。
- 驼：将“准噶尔双峰驼”归一为官方名“新疆准噶尔双峰驼”，旧名保留为别名。
- 鸡：河田鸡、金阳丝毛鸡、林甸鸡、怀乡鸡、闽清毛脚鸡、皖南三黄鸡、金湖乌凤鸡、烟台䅟糠鸡、淅川乌骨鸡、河南斗鸡、景阳鸡、来凤酉水鸡、雪峰乌骨鸡、广西麻鸡、瑶鸡、腾冲雪鸡、太平鸡、海东鸡。
- 鸭：龙岩山麻鸭、麻旺鸭；现有“山麻鸭”先作为同名关系候选核验，确认属于同一品种时做更名和别名迁移，不重复新增。
- 鹅：向海飞鹅。
- 鹿：吉林梅花鹿。
- 驯鹿：将“驯鹿”归一为官方名“敖鲁古雅驯鹿”，旧名保留为别名。

预计实际新增约 20–25 条，最终数量由逐条核验结果决定。无法找到足够可靠的产地、坐标、性状或图片依据时，宁可标记待补充或暂缓加入，也不编造完整记录。

### 5.3 数据结构与来源模型

在保持现有 `Breed` 展示字段兼容的基础上，增加独立的元数据层，避免为全部对象机械复制相同来源：

- `aliases`：可搜索的旧称、简称和异体名称。
- `officialName`：与当前权威名录一致的规范名称。
- `protectionStatus`：`national-list`、`not-on-national-list` 或 `unverified`。
- `sourceIds`：指向统一来源目录，来源目录记录标题、发布机构、URL、发布日期、核对日期和适用范围。
- `verifiedAt`：该记录最后人工核对日期。
- `imageSource` / `imageRights`：在信息可得时记录图片来源和版权状态；不可确认时明确显示“来源待核验”，不作版权保证。

遗留记录至少解析到“项目既有整理数据集”来源，并明确其核验状态；本轮新增和官方名称归一记录必须指向第 940 号公告及相应补充资料。详情页提供紧凑的“数据来源与核验”区块。

### 5.4 唯一性与兼容

- 所有 `id` 必须全局唯一且稳定，使用可读的规范名称 slug；同省或同类重名时添加明确限定词，不使用随机后缀。
- 修复 11 组重复 ID，并为被改动记录保留 `legacyIds` 映射；所有查找先走新 ID，再兼容旧入口，避免现有分享链接静默指向另一记录。
- 名称、别名和英文名共同参与搜索；规范名始终作为主标题。
- 页面总数和分类统计从实际数据实时计算，文档统计由审计脚本生成或校验，不再手工散落维护。

### 5.5 自动数据审计

新增可在测试和命令行复用的审计规则，至少检查：

1. ID 与规范中文名唯一。
2. 必填文本非空，图片字段合法。
3. 经度 `[-180, 180]`、纬度 `[-90, 90]`，中国品种的异常坐标单独提示。
4. 分类和濒危等级属于已知枚举。
5. 五项雷达值为 0–100 的有限数字。
6. 所有记录都能解析到来源，国家级名录标记能解析到公告。
7. `aliases` 不与另一品种规范名发生歧义。
8. README、网站说明书和数据手册中的总数、分类数与运行数据一致。

## 6. SVG 品牌系统设计

### 6.1 核心概念

品牌图形采用已确认的“馆藏印章＋屋檐＋双角/叶脉”：

- 外轮廓取方中带圆的馆藏印章，体现权威、档案与中华传统。
- 上部用简化屋檐表达“博物馆”和庇护。
- 中部一笔分叉，同时可读为家畜双角和植物叶脉，连接“畜禽遗传资源”与生命延续。
- 图形保持小尺寸可识别，不堆叠生肖剪影和细碎装饰。

### 6.2 资产集合

新增并统一使用：

- `museum-mark.svg`：方形徽标，供页头、移动菜单和社交预览角标使用。
- `museum-wordmark.svg`：横版徽标与馆名组合，供宽屏页头、文档和品牌展示使用。
- `favicon.svg`：针对 16–32px 重新简化的单图形版本。
- `breed-placeholder.svg`：图片加载失败或无图时的宣纸纹理式占位，包含简化双角/叶脉和“图像待补”语义。

原 `public/images/logo/` 中遗留的 TailAdmin logo 不再被页面引用，并由新品牌资产替换或删除；页头的临时单字圆标改为真实 SVG。`index.html` 改用 SVG favicon，同时保留必要的兼容声明。

### 6.3 色彩与可访问性

- 主墨绿：`#173B2C` 附近；宣纸：`#F4EFE3` 附近；鎏金：`#C79A45` 附近；朱砂只作极少量状态点缀。
- 所有正文与交互状态满足 WCAG AA 对比度；金色不作为浅底小字号正文色。
- 纯装饰 SVG 使用空 `alt`；品牌标志由邻近文本或可访问名称说明；独立图标包含 `<title>`。
- SVG 不引用远程字体、脚本或栅格数据，路径和元素数量保持克制。

## 7. 页面与交互改造

### 7.1 全局布局与导航

- 保留墨绿顶栏、宣纸内容面和金色强调，统一边框、阴影、圆角、字号和间距节奏。
- 桌面端展示横版品牌；窄屏使用徽标，并把次要操作收纳为明确菜单。
- 移动端采用可完整到达的菜单/底部导航方案，消除横向截断；搜索以独立入口展开，不与主题、语言按钮挤在同一行。
- 所有主要触控目标至少 44×44px；当前页面状态同时用颜色和形态表达。
- 加入“跳到主要内容”链接，`main` 有稳定 id，每页只有一个清晰 H1。
- 页脚的更新时间和收录数量从数据版本与实际记录计算。

### 7.2 地图、百科、看板与对比

- 地图筛选在桌面保留侧栏，在移动端使用带结果数的抽屉；详情采用适合窄屏阅读的底部面板，避免地图和长文互相争夺空间。
- 搜索和筛选结果提供可感知的数量、空状态和清除条件入口。
- 百科卡片保持图片区域尺寸稳定；图片失败时切换到 SVG 占位，不隐藏容器，不重复触发错误。
- 看板图表提供文字摘要、可读标签和非颜色唯一编码；小屏避免标签重叠。
- 对比页明确最少/最多选择数，移动端允许横向对照但固定品种名称，并为雷达图提供文字数据表。

### 7.3 AI 页面与降级

- 静态页面不得依赖 Supabase 初始化。客户端改为按需、可空创建，仅 AI 或确有后端需求的功能加载。
- 未提供环境变量时，AI 页面显示清楚的“服务未配置”说明和返回科普内容的入口，不白屏、不抛出未捕获异常。
- 网络失败、接口超时和无响应分别给出可恢复状态；不在前端日志打印凭据或完整敏感请求。

### 7.4 404、错误与离线感知

- 未知路由渲染真正的 404 页面，保留请求路径，提供返回首页和进入百科的操作。
- 全局错误边界改用项目品牌样式并提供重试；错误文案不暴露堆栈。
- 断网提示使用非阻塞状态条，现有静态数据仍可浏览。

## 8. 性能与加载设计

- 页面组件改为 `React.lazy` 路由级拆包，首屏只加载首页和共享壳层。
- AI、PDF 导出、截图、二维码和 Recharts 等重依赖在对应功能首次使用时动态导入。
- 为路由懒加载提供符合品牌的轻量 skeleton，并对常用下一页做空闲时预取，而不是全部预载。
- 图片补充 `loading`、`decoding`、明确宽高/宽高比和 SVG 失败回退，减少布局跳动。
- 修复 Vite ESM 路径配置，使用 `import.meta.dirname` 或 `fileURLToPath(import.meta.url)`，消除 `__dirname` 警告。
- 构建报告记录各入口 chunk；验收重点是首屏主 chunk 显著小于当前约 2.63 MB，AI/PDF/图表形成独立异步块。

## 9. SEO、国际化与内容语义

- 在应用根部正确接入 Helmet provider，每条路由设置独立中文 title、description、canonical 和基础 Open Graph 信息。
- `index.html` 提供无 JavaScript 时也存在的站点默认 title、description、theme-color 和 SVG favicon。
- 每页建立 H1–H3 语义层级；按钮、导航、表单标签和图表摘要对辅助技术可理解。
- 语言切换保留，但不宣称完整英文站：缺少英文内容时保持中文并显式标注，避免混合翻译造成误导。新增文案必须同时进入翻译字典或有明确中文回退。
- 站点为客户端路由且部署于 GitHub Pages 子路径时，继续使用兼容的路由与资源基址；404 回退策略写入部署文档。

## 10. 安全、隐私与配置

- 停止跟踪真实 `.env.production`，新增不含值的 `.env.example`，README 说明哪些变量仅用于 AI/后端能力。
- Supabase anon key 本质上会下发给浏览器，但仍需依赖数据库 RLS 和 Edge Function 鉴权；文档不得把“未泄露 anon key”当作安全边界。
- 不在客户端引入 service role key，不输出环境变量、请求认证头或用户输入全文到日志。
- 外链内容按 URL 使用，不把不可信 SVG 以内联 HTML 注入；文本继续由 React 转义。
- 运行依赖审计并区分可利用风险、开发依赖告警和无影响告警，不为追求零告警盲目大版本升级。

## 11. 测试策略

实现遵循测试先行。修改测试前先阅读项目适用的高质量测试规范；测试观察用户可见行为和稳定数据契约，不绑定内部实现细节。

### 11.1 Vitest

- 数据审计：唯一 ID/名称、坐标、枚举、雷达范围、来源、别名冲突和统计。
- 搜索与别名：规范名、旧称、英文名均能命中正确且唯一的记录。
- 图片回退：加载失败后显示占位并保持容器，回退自身失败不循环。
- 配置降级：无 Supabase 环境变量时静态页面可渲染，AI 页面显示未配置状态。
- 路由与元信息：每条已知路由有正确标题，未知路径显示 404。
- 布局与无障碍：跳转主内容、菜单可访问名称、关键键盘操作和减少动画分支。

### 11.2 Playwright

- 桌面视口：加载首页，进入地图，搜索并打开详情，进入看板、百科、对比和 404。

## 15. 主要风险与缓解

- **官方名与站内记录不完全一一对应**：逐条记录判断依据和别名，不用字符串差集直接批量新增。
- **现有图片来源和版权不透明**：不扩大未经核实的版权声明；用占位和索引明确状态，后续分批替换。
- **修复重复 ID 可能改变内部引用**：引入旧 ID 映射并用搜索、详情和地图测试覆盖。
- **大范围 UI 改动引发回归**：先建立烟雾测试，再按共享壳层到页面逐步改造。
- **拆包后出现加载闪烁或 GitHub Pages 路径问题**：提供统一 fallback，使用现有相对基址并以生产预览验证深链和异步资源。
- **英文界面覆盖不完整**：本轮只保证新增界面文案有英文或明确回退，不把数据全文翻译作为隐含范围。
