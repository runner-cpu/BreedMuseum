## 1. 本轮目标与结果

本轮按用户确认的 C「沉浸实验」方向，参照原站 `https://app-dr6mrcqei51d.appmiaoda.com/map` 和用户截图，修正地图探索页的排版、知识卡片比例、缺图记录处理和馆藏助手拖拽行为。路由、数据字段和页面骨架保持不变。

已完成：

- 地图面板增加标题带和馆藏总数，筛选条下移到画布上方，坐标提示不再压住筛选控件；桌面、窄桌面和移动端均保持独立布局。
- 地图右侧详情卡改为媒体头、中文名/英文名、状态、产区/类别、操作按钮和故事段落的层级；图片使用更接近原站的 `aspect-[1.55]` 比例，避免原先 `h-28` 横幅裁切和下半区空白。
- `BreedImage` 增加 `hasBreedImage` 和显式空状态。首页精选卡、百科视觉卡片不再展示 `/brand/breed-placeholder.svg`；搜索命中缺图记录时显示“待补图片的资料记录”文本入口，仍可打开详情查看文字资料。
- 地图首屏、产区点击和簇点击优先选择有实际图片的记录；一个省份完全没有可用图时不强行展示示意图。
- 百科详情仍保留无图记录的文字详情，但使用“图片待补充”状态，不把插画占位当作真实图片。
- AI 助手固定在右侧，只响应 `clientY` 垂直移动，横向拖动不会改变位置；按钮提示图标改为 `MoveVertical`。

本轮没有生成新的栅格图片，也没有改写馆藏统计口径。现有外链图片仍沿用原数据来源，Wikimedia Commons 的本地授权图片登记表仍为空。

## 3. 已知边界

- 当前仍有约数百条记录依赖已有外链图片或占位图；本轮只保证视觉卡片不主动展示占位图，没有完成全量图片溯源。
- “缺图记录”仍存在于 `breeds`、地图点位和文字详情中，因为它们是馆藏资料，不应因缺图破坏检索和统计。视觉卡片和精选卡片才按有图过滤。
- 地图点击的是无图品种时，会尝试展示同省份第一条有图记录；如果同省份完全没有有图记录，详情卡收起。这是当前“地图数据完整、视觉卡片不伪造”的折中策略。
- 构建仍会提示 `breeds`、`DashboardPage` 等既有大 chunk，属于历史问题，本轮没有引入新的重型依赖。

## 5. 后续执行顺序

### P0：锁定视觉与回归基线

1. 在 1920×900、1440×900、390×844 三个视口检查地图标题带、筛选条、坐标提示、详情媒体比例和移动端底部详情卡。
2. 补一个助手拖拽 E2E：水平拖动前后 `right` 不变，垂直拖动只改变 `bottom`，点击仍能开关面板。
3. 运行完整 `pnpm check:all`，确认文档同步、包体预算、Pages 构建和全量 E2E 都通过。

### P1：补齐图片来源

1. 依据 `tasks/breed-image-plan.json` 和 `tasks/source-commons-images.mjs`，从 Wikimedia Commons 等可核验渠道为高频展示品种补图。
2. 每个新增图片必须同时登记本地路径、作者、许可证、来源页和文件标题到 `src/data/breedImageOverrides.ts`，再运行图片审计测试。
3. 下载前后检查实际图片尺寸、主体是否为对应品种和许可证字段；无法核验的记录继续留在文字入口，不要伪造图片。

### P2：再做结构性优化

- 评估把地图筛选、图例和坐标提示抽成更清晰的可访问控件，保持键盘和触屏可用。
- 按数据质量报告处理 `breeds` 大 chunk；不要为了消除警告引入大型地图或动效依赖。
- 继续维持 `prefers-reduced-motion` 降级、现有路由兼容入口和 `COLLECTION_SUMMARY` 统计口径。

## 6. 交接完成标准

队友完成以下事项后，才算结束本批次：

- 完整门禁通过并有可复现的 E2E 结果；
- 三种视口截图确认地图与详情卡没有重叠、裁切或横向溢出；
- 助手只能上下移动，且不会因拖动误触打开/关闭；
- 缺图记录不会出现在精选/百科图片卡片中，但仍能通过搜索进入文字详情；
- 新增图片都有来源、许可证和本地登记；
- 修改通过独立提交推送到 `origin/main`，并检查 GitHub Actions 的 quality、Pages build 和 deploy 阶段。
