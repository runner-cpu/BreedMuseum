# BreedMuseum 项目交接文档

更新日期：2026-10-17

远端仓库：https://github.com/runner-cpu/BreedMuseum

## 1. 本轮目标与结果

本轮按用户确认的 C「沉浸实验」方向，参照原站 `https://app-dr6mrcqei51d.appmiaoda.com/map` 和用户截图，修正地图探索页的排版、知识卡片比例、缺图记录处理和馆藏助手拖拽行为。路由、数据字段和页面骨架保持不变。

已完成：

- 地图面板增加标题带和馆藏总数，筛选条下移到画布上方，坐标提示不再压住筛选控件；桌面、窄桌面和移动端均保持独立布局。
- 地图右侧详情卡改为媒体头、中文名/英文名、状态、产区/类别、操作按钮和故事段落的层级；图片使用更接近原站的 `aspect-[1.55]` 比例，避免原先 `h-28` 横幅裁切和下半区空白。
- 新增 `src/data/breedImage.ts` 与 `src/data/visibleBreeds.ts`，统一以 `/brand/breed-placeholder.svg` 判定缺图；首页精选、百科、地图、看板地图、对比、互动厅关联卡和助手问答只消费 `visibleBreeds`。
- 百科不再展示“待补图片”区域，也不允许通过 `?breed=` 打开缺图详情；缺图搜索直接进入空状态。
- 地图首屏、产区点击和簇点击只来自有图记录；地图统计摘要按可展示记录计算。原始 `breeds` 仍保留给数据审计、名录覆盖和质量测试，不把展示删除误写成台账删除。
- AI 助手浮动按钮恢复为窗口内任意方向移动，使用 `x/y` 坐标、指针捕获、边界约束和拖动后不误触开关；按钮提示图标改为 `Move`。

本轮没有生成新的栅格图片，也没有改写馆藏统计口径。现有外链图片仍沿用原数据来源，Wikimedia Commons 的本地授权图片登记表仍为空。

## 2. 关键文件

| 文件 | 责任 | 接手提示 |

| `src/pages/ExploreMapPage.tsx` | 地图筛选、右侧详情卡、无图记录选择策略 | 详情卡只接收有图记录；不要在 JSX 写新的统计数字 |
| `src/components/ChinaMap.tsx` | SVG 地图、点位、图例和坐标提示 | `.museum-map-coordinate-note` 负责移动端提示定位，修改后要复测 390px |

| `src/components/common/BreedImage.tsx` | 图片 URL 解析、失败回退、缺图判断 | `hasBreedImage` 只用于视觉卡片筛选；详情页可用 `fallbackMode="empty"` |
| `src/data/visibleBreeds.ts` | 访客可见馆藏边界 | 所有视觉入口统一使用，不能在页面内重新直接消费完整 `breeds` |
| `src/pages/EncyclopediaPage.tsx` | 百科图片卡片与缺图空状态 | 缺图记录不显示卡片、按钮或详情入口 |
| `src/pages/LightMapPage.tsx` | 首页精选品种卡片 | `featured` 必须继续过滤无图记录 |
| `src/components/assistant/LocalAssistant.tsx` | 馆藏助手浮动按钮和问答 | 位置状态为 `position.x / position.y`；保持窗口边界与拖动防误触 |

## 3. 已知边界

- 当前仍有约数百条记录依赖已有外链图片或占位图；本轮没有完成全量图片溯源。
- 缺图记录从所有访客视觉入口和助手问答中移除，但仍留在 `breeds` 原始台账与数据审计测试中；新增图片后只需移除占位图或登记 `breedImageOverrides`，即可自动进入访客集合。
- 地图只接收 `visibleBreeds`，因此不会再产生“点到无图记录后替换成同省份记录”的路径；同省份无含图坐标时不显示详情卡。
- 构建仍会提示 `breeds`、`DashboardPage` 等既有大 chunk，属于历史问题，本轮没有引入新的重型依赖。

## 5. 后续执行顺序

### P0：锁定视觉与回归基线

1. 在 1920×900、1440×900、390×844 三个视口检查地图标题带、筛选条、坐标提示、详情媒体比例和移动端底部详情卡。
2. 补一个助手拖拽 E2E：水平和垂直拖动都改变按钮位置，按钮不超出窗口，拖动结束不会误打开面板，点击仍能开关面板。
3. 运行完整 `pnpm check:all`，确认文档同步、包体预算、Pages 构建和全量 E2E 都通过。

### P1：补齐图片来源

1. 依据 `tasks/breed-image-plan.json` 和 `tasks/source-commons-images.mjs`，从 Wikimedia Commons 等可核验渠道为高频展示品种补图。
2. 每个新增图片必须同时登记本地路径、作者、许可证、来源页和文件标题到 `src/data/breedImageOverrides.ts`，再运行图片审计测试。
3. 下载前后检查实际图片尺寸、主体是否为对应品种和许可证字段；无法核验的记录继续留在文字入口，不要伪造图片。

### P2：再做结构性优化

- 评估把地图筛选、图例和坐标提示抽成更清晰的可访问控件，保持键盘和触屏可用。
- 按数据质量报告处理 `breeds` 大 chunk；不要为了消除警告引入大型地图或动效依赖。
- 继续维持 `prefers-reduced-motion` 降级、现有路由兼容入口和 `COLLECTION_SUMMARY` 统计口径。

## 6. 交接完成标准

队友完成以下事项后，才算结束本批次：

- 完整门禁通过并有可复现的 E2E 结果；
- 三种视口截图确认地图与详情卡没有重叠、裁切或横向溢出；
- 助手可以在窗口内任意方向移动，且不会因拖动误触打开/关闭；
- 缺图记录不会出现在精选、百科、地图、对比、互动厅关联卡或助手问答中；
- 新增图片都有来源、许可证和本地登记；
- 修改通过独立提交推送到 `origin/main`，并检查 GitHub Actions 的 quality、Pages build 和 deploy 阶段。
